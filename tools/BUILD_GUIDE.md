# 制作手順書 — ヒアリング回答から1ページサイトを作る

`create_hearing_form.gs` のフォームに回答が届くと「【制作指示書】店名」メールが届く。
その本文（または添付 .md）を Claude Code に貼り、`/simple-hp-build` で実行すると、この手順どおりに作る。
**同じ指示書からは、誰が何回作っても同じ構成・同じ品質になる**ことを目的にしている。

- 商品の範囲: 1ページ完結・¥25,000・月額¥0（LP の「含まれるもの／含まれないもの」が正）
- 参考実装: `works/owl-koiwa/index.html`（納品済みの1ページサイト。構成・技術スタックの基準）
- デザインの引き出し: サンプル V1〜V6（`https://ota-sanpot.github.io/sample_store{,_v2..._v6}/`）

---

## 0. 絶対ルール

1. **事実は指示書にあるものだけ。** 店名・住所・電話・営業時間・定休日・価格・メニュー名・席数・支払い方法・SNSのURLは、1文字も推測で作らない。無いものは載せないか、`要確認` として確認リストに出す。
2. **誇張しない。** 「No.1」「日本一」「最高級」「必ず」など根拠のない最上級・断定は使わない（景品表示法）。指示書にある事実を言い換えて魅力を伝える。
3. **範囲外は作らない。** 予約システム・ネット注文・ブログ・英語ページ・複数ページは作らない（希望があれば確認リストに「別見積もり」として出す）。
4. **載せたくない情報**（⑨）と**名前・写真の掲載可否**（③）を最優先で守る。
5. **写真と料理名を必ず一致させる。** 料理名の横に置く写真は、その料理そのものの写真だけ。合う写真が無ければ写真なしのレイアウトにする（別の料理の写真で埋めない）。
6. 迷ったら下の「既定値」を使い、何を既定値で決めたかを最後の報告に必ず書く。

---

## 1. 取り込みと不足チェック

1. 店名から英小文字のスラッグを決める（例: `owl-koiwa` = 店名＋地名）。作業場所は `works/<slug>/`。
2. 指示書を `works/<slug>/brief.md` にそのまま保存する（原本。編集しない）。
3. 写真を `works/<slug>/images/_raw/` に置いてもらう（無ければ仮画像で進め、差し替え前提と明記）。
4. 下の **必須事実** が揃っているか確認する。欠けていれば制作前に CEO へ「お客様への確認事項」として一覧で返す（勝手に埋めない）。

| 必須事実 | 指示書の項目 |
|---|---|
| 店名・読み | ① 店名（正式表記）／店名の読み |
| 住所・アクセス | ① 住所／最寄り駅と道順 |
| 電話（または掲載しない指定） | ① ホームページに載せる電話番号 |
| 営業時間・定休日 | ① 営業時間／定休日 |
| 看板メニュー（品名・価格） | ④ 看板メニュー／価格表示 |
| 主目的・最後の行動 | ② 一番の目的／最後にしてほしい行動 |

---

## 2. 設計表を作る（`works/<slug>/spec.md`）

コードを書く前に、指示書を下の表に**機械的に**変換して `spec.md` に書く。ここが再現性の要。

### 2-1. 主役とボタン（② 目的 → 構成）

| 最後にしてほしい行動 | 主ボタン（ヒーロー・固定ボタン・最後のCTA） |
|---|---|
| 電話で予約・問い合わせ | `tel:` リンク「電話で予約する」＋番号を大きく表示 |
| ネット予約 | ⑦ 予約ページURL「ネットで予約する」（URLが無ければ `要確認`） |
| LINEで予約・友だち追加 | ⑦ LINE URL「LINEで予約・相談」 |
| Instagramを見てフォロー | ⑦ Instagram「Instagramを見る」 |
| Googleマップで道順→来店 | ⑦ GoogleマップURL「地図で道順を見る」（無ければ住所検索URL） |

2番目の行動は副ボタン（アウトライン）にする。未回答なら「地図で道順を見る」。

| 一番の目的 | ヒーロー直下に置く要素 |
|---|---|
| 新しいお客様に見つけてもらいたい | 業態・駅・徒歩分数を1行で（例:「蒲田駅 徒歩3分／海鮮居酒屋」） |
| SNS等から来た人に魅力を伝えたい | 「違うところ3つ」をアイコン付き3カラム |
| 予約を増やしたい | 主ボタンを2か所（ヒーロー・メニュー直後）＋スマホ固定ボタン |
| 宴会・団体・貸切 | コース・飲み放題セクションをメニューより前に |
| ランチ・テイクアウト | ランチ／テイクアウトを独立セクションに、時間帯を強調 |
| 取引先・取材・採用 | 想い・店主の経歴を厚めに、開業年を表示 |

### 2-2. セクション構成（この順で固定。条件付きは該当時のみ）

1. **ヒーロー** — 店名・キャッチコピー・一言紹介・主ボタン／副ボタン・（目的別の要素）
2. **想い（コンセプト）** — ③ 違うところ3つ・きっかけ・必ず伝えたいこと
3. **看板メニュー** — ④ 看板メニュー（写真ありを大きく）
4. *条件* **コース・飲み放題・ランチ**（④ に記載がある時）
5. **お品書き** — ④ その他のメニュー（「看板メニューだけ」なら省略、「メニュー表の写真」なら写真から文字起こしして CEO に確認依頼）
6. **店内（ギャラリー）** — 店内・外観写真、⑤ 席数
7. *条件* **店主紹介**（③ で名前か写真の掲載OKの時）
8. **ご利用案内** — ⑤ 予算・当てはまるもの・支払い・喫煙・お通し・ルール（未回答は行ごと出さない）
9. **店舗情報・アクセス** — 店名／住所／道順／電話／営業時間／定休日／Googleマップ埋め込み
10. **予約・CTA** — 主ボタン＋副ボタン＋SNSアイコン
11. **フッター** — 店名・住所・SNS・© 表記

スマホでは主ボタンを画面下に固定する（ヒーローを過ぎたら表示、アクセス到達で隠す）。

### 2-3. デザイン値（⑥ → トークン）

**ベースのサンプル**: ⑥「いちばん近いサンプル」の1つ目を骨格にする。2つ目は差し色・装飾の参考に。「どれも違う」／未回答なら業態で決める。

| 業態 | 既定のサンプル |
|---|---|
| 和食・割烹 | V1 |
| 居酒屋・海鮮・寿司 | V2 |
| カフェ・喫茶・ベーカリー・スイーツ | V3 |
| 焼肉・焼き鳥 | V4 |
| バー・ワインバー・イタリアン・フレンチ・洋食 | V5 |
| ラーメン・町中華・アジア・エスニック | V6 |

**明るさ**: 暗め→背景 `#14110E` 系＋明るい文字／明るめ→背景 `#FBF8F1` 系／中間→背景 `#EFE6D8` 系＋木目調の写真を多めに／お任せ→ベースサンプルに従う。

**色**: テーマカラーがあれば `primary` にそのまま使う（写真の看板・のれんから色を拾う）。NG色は差し色にも使わない。未回答ならベースサンプルの配色。

**文字**（Google Fonts）:

| 回答 | 見出し | 本文 |
|---|---|---|
| 明朝体 | Shippori Mincho B1 | Noto Serif JP |
| ゴシック体 | Zen Kaku Gothic New（700） | Noto Sans JP |
| 手書き風 | Zen Maru Gothic（見出しのみ Klee One 可） | Zen Maru Gothic |
| お任せ | ベースサンプルのフォント | ベースサンプルのフォント |

英字の飾り（セクション名など）は Cormorant Garamond か Oswald をサンプルに合わせて1種だけ使う。日本語に italic は当てない。

**雰囲気の言葉**（最大3つ）は余白・写真の大きさ・動きの強さに反映する: 高級感/落ち着き→余白広め・動き控えめ／にぎやか・活気・力強い→写真大きめ・太字・コントラスト強め／かわいい・温かみ・ナチュラル→角丸・やわらかい色。

**文章のトーン**: 丁寧・上品＝です・ます＋体言止め少なめ／親しみやすい＝話し言葉を少し混ぜる／職人らしく簡潔＝短文・体言止め中心／お任せ＝業態とサンプルに合わせる。

### 2-4. コピー

- キャッチコピー: 指示書に案があればそれを使う。「お任せ」なら ③ の「違うところ」「褒め言葉」「必ず伝えたいこと」から **3案** 作り、spec.md に並べて1案目で実装する（CEO が差し替えられるように）。
- 褒め言葉は「お客様の声」として創作しない。紹介文の言い回しに溶かすだけ（レビューの捏造は禁止）。
- メニューの価格表記は ④ の税込／税抜に統一（例: `1,980円` か `1,980円（税抜）`）。

## 3. 実装

- 1ファイル `works/<slug>/index.html`（Tailwind CDN＋インラインCSS/JS。`owl-koiwa` と同じ作り）。
- 画像: `_raw/` から選び、長辺1600px程度の jpg/webp に書き出して `images/` へ（`hero.jpg`・`menu-01.jpg`…・`store-01.jpg`…の命名）。人物写真は掲載許可が「許可は取っている」の時だけ使う。
- 必須の head: `title`（店名｜駅名・業態）・`description`（業態・駅・特徴を120字前後）・OGP・favicon（ロゴから生成。無ければ店名の頭文字）。
- 構造化データ: `application/ld+json` の `Restaurant`（name / address / telephone / openingHours / servesCuisine / url / image / priceRange）。指示書にある値だけ入れる。
- 電話は `tel:` リンク、地図は Google マップ埋め込み（GoogleマップURLが無ければ住所で `maps?q=` 埋め込み）、外部リンクは `target="_blank" rel="noopener"`。

---

## 4. 検証（全部やってから報告）

1. **事実照合**: brief.md の必須事実・価格・営業時間を、生成した HTML の表示テキストと1項目ずつ突き合わせ、一致表を spec.md に残す。
2. **写真照合**: 料理名・見出しの横にある写真を1枚ずつ目視し、内容が一致していることを確認する。
3. **表示確認**: 375px・768px・1440px でスクリーンショットを撮り、はみ出し・重なり・文字切れ（見出しの1文字落ちを含む）が無いことを目視。
4. **リンク**: 主ボタン・副ボタン・SNS・地図・電話がすべて正しい先に飛ぶ。
5. **禁止事項**: 範囲外機能が無い／載せたくない情報が載っていない／根拠のない最上級表現が無い／ダミー文字（◯◯・Lorem・仮）が残っていない。

---

## 5. 報告（CEO へ）

次の順で短く報告する。
1. プレビューの見方（ローカルのURL）とスクリーンショット
2. **お客様への確認事項**（`要確認` の一覧。そのままLINEに貼れる文面で）
3. **既定値で決めたこと**の一覧（どの未回答をどう埋めたか）
4. キャッチコピー3案（お任せの場合）

公開（GitHub Pages・ドメイン設定・push）は CEO の OK が出てから。
